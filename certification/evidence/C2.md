# C2 Certification Evidence — Live KataGo Runtime

Candidate: **1.0.0-rc.3**  
Supersedes: **1.0.0-rc.2**

## Why rc.3 exists

C2 found that the canonical GitHub Pages application could not use the P11
same-origin `/api/katago/*` assumption because GitHub Pages is static hosting.

rc.3 adds a production-configurable external proxy boundary:

```
VITE_KATAGO_API_BASE
```

and keeps bridge credentials server-side.

## Implemented C2 controls

- external proxy endpoint support in the browser;
- canonical local fallback path when no proxy is configured;
- proxy CORS allowlist;
- best-effort per-instance public request limiting;
- request-body, board-size, move-count, analyze-turn, visit, PV, allowMoves,
  and override-setting caps;
- bounded proxy timeout;
- explicit bridge 409/429/503/504 failure status;
- Vercel function duration configuration;
- production Pages injection via repository variable `KATAGO_API_BASE`;
- live 9×9, 13×13, and 19×19 certification script;
- post-deploy `katago-live-qa` workflow;
- explicit deterministic Review fallback test.

## Required live production evidence

C2 is certified only when all of the following pass against a real production
runtime:

1. proxy health: configured + ready;
2. 9×9 analysis;
3. 13×13 analysis;
4. 19×19 analysis;
5. candidates + root data + correctly sized ownership;
6. public 20×20 rejection;
7. timeout/failure leaves deterministic Review usable;
8. public workload guards remain active.

## External activation blocker

Attempting to create the dedicated Vercel project `go-katago` through the
connected Vercel account returned HTTP 403:

> Not authorized: Trying to access resource under scope "thiepn-project".
> You must re-authenticate to this scope or use a token with access to this scope.

The connector can read existing Vercel projects in team
`team_LVo30en2fIX29vZH3gnYxmoi`, but cannot currently create resources in that
scope.

This is an external-account authorization gate. It is not treated as passing
evidence and C2 must not be marked certified until the scope is re-authorized,
the proxy is deployed, a persistent KataGo/model host is active, and
`katago-live-qa` succeeds.

## Decision

Status: **implementation candidate ready for repository CI; live certification
blocked by Vercel authorization / engine-host activation**.

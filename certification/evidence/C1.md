# C1 Certification Evidence — Canonical /go/ Deployment

Candidate: **1.0.0-rc.2**  
Supersedes: **1.0.0-rc.1**

## Why rc.2 exists

C1 found a release-blocking mismatch in rc.1:

- the release contract declared `https://thiepn.dev/go/`;
- Vite still built with root `/`;
- the PWA manifest used root start URL/scope/icon paths;
- the service worker attempted root registration and root shell caching.

That behavior could not be certified as a project app under `/go/`.

Per the C0 invalidation policy, the correction is a new behavioral candidate:
`1.0.0-rc.2`.

## rc.2 canonical contract

- Vite base: `/go/`;
- canonical URL: `https://thiepn.dev/go/`;
- manifest start URL: `/go/`;
- manifest scope: `/go/`;
- service worker script: `/go/sw.js`;
- service worker scope: `/go/`;
- production assets: `/go/assets/*`;
- offline shell/navigation fallback: `/go/`;
- generated lazy chunks: precached using `/go/assets/*` URLs.

## Post-deploy evidence

After merge, Pages must deploy the exact merged rc.2 SHA.

The `canonical-deploy-qa` workflow then runs against:

`https://thiepn.dev/go/`

and must prove:

1. `release.json` candidate/version are `1.0.0-rc.2`;
2. deployed `sourceCommit` equals the Pages release SHA;
3. manifest start URL/scope are `/go/`;
4. manifest icons are under `/go/`;
5. document assets do not leak to root app paths;
6. `/go/sw.js` is active with `/go/` scope;
7. production refresh succeeds;
8. production reload succeeds while offline;
9. a lazy-loaded first lesson opens while offline from the installed precache.

Final live run ID, merged SHA, and pass/fail decision are recorded on PR #7 after
deployment so the behavioral source SHA is not changed by a post-certification
documentation commit.

# C3 Certification Evidence — Production Account & Sync

Candidate: **1.0.0-rc.4**  
Supersedes: **1.0.0-rc.3**

## Why rc.4 exists

C3 found a release-blocking recovery gap in rc.3:

- Go could call the central SDK to send a password-reset email;
- the central THIEPN Account SDK correctly emits `PASSWORD_RECOVERY` and exposes
  `updatePassword`;
- Go did not recognize that recovery event or expose a password-update UI.

That meant the product could start recovery but could not complete it. rc.4 adds
the missing recovery-session state and UI.

## Implemented C3 controls

- auth-state subscription is installed before initial session resolution;
- canonical `PASSWORD_RECOVERY` events enter recovery mode;
- recovery sessions automatically open the Account workspace;
- new password + confirmation UI;
- password completion goes through central SDK `updatePassword`;
- successful password replacement leaves the local account session intact;
- recovery state clears on completion or local sign-out;
- non-destructive production account smoke workflow;
- dedicated destructive credentialed sync workflow;
- backup export/import production smoke;
- Google OAuth initiation/redirect-target smoke;
- password-reset initiation/redirect-target smoke.

## Automatic public production evidence

After rc.4 reaches Pages, `account-production-qa` runs against:

`https://thiepn.dev/go/`

It proves:

1. signed-out boot works without an account;
2. backup remains available while signed out;
3. Google OAuth initiation targets the canonical THIEPN Account project and
   returns to `https://thiepn.dev/go/`;
4. password-recovery initiation uses the canonical return URL without sending a
   real test email;
5. portable backup export/import preserves durable Go progress.

## Dedicated credentialed evidence

`account-c3-certification` is intentionally manual and destructive. It
requires repository environment secrets:

```
C3_TEST_EMAIL
C3_TEST_PASSWORD
```

They must belong to a dedicated disposable THIEPN Account test identity, never a
personal account.

The workflow proves:

1. cloud Go state can be cleared without deleting account/local data;
2. existing local progress merges upward on first sign-in;
3. a second device with newer local progress merges without rollback;
4. simultaneous device changes converge monotonically;
5. a previously authenticated device keeps local learning usable offline;
6. returning online resyncs without forcing logout;
7. local sign-out does not sign out the other device;
8. Go-only cloud deletion leaves local Go state and account identity intact.

## Remaining interactive auth gates

Two requirements cannot be truthfully automated without a real provider session
or access to the dedicated test mailbox:

### Google OAuth return

Automatic smoke verifies provider initiation and canonical redirect parameters.
C3 certification additionally requires one successful interactive Google login
that returns to `https://thiepn.dev/go/` with the same THIEPN identity.

### Password recovery return

Automatic smoke verifies reset request routing, and rc.4 implements/tests the
recovery-event state. Certification additionally requires one real recovery
email to the dedicated test inbox, opening its one-time recovery URL, setting a
new password in Go, and signing in with that new password.

These are manual evidence gates, not code TODOs.
